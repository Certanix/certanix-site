CERTANIX

Verify an evidence pack

Check a Certanix evidence pack yourself, on your own machine, without contacting us. This page does it in your browser. The command line does it anywhere, including a machine with no network at all.

What verification proves

  • The content is exactly what was signed The verifier recomputes the pack's canonical bytes from the document you hold and checks them against the signature inside it, using a public key you supply. Change one value and the check fails. Reformatting the file (indentation, key order) does not change its content, so it still verifies.
  • It was signed by the holder of that key Only the private key that matches the public key can produce a signature that checks. When the public key is the Certanix key below, and you have confirmed its fingerprint, the pack was signed by Certanix's hardware-held signing key.
  • It is well formed, and claims nothing its own record denies The pack must match the published schema for its version. It must also not claim a capability that its own recorded capability gate refuses. A pack whose signature is valid but which breaks either rule does not verify.

What it does not prove

  • That the results are true, or that the system is safe. A signature shows who signed and that nothing changed since. It does not show that what was recorded is correct.
  • That anyone has approved the system. An evidence pack is pre-certification evidence. Certanix does not certify, type-approve or authorise anything, and no verification result is a decision of a notified body or an authority.
  • Whose key it is, on its own. A signature checks against whatever key it is given. Confirm the key's fingerprint through a channel you already trust before you rely on a result.
  • When it was signed, or that it is the latest version. Verification does not establish a signing date or rule out a newer, superseding pack. A trusted timestamp, where a pack has one, is checked separately (certanix-verify vault).
  • That the key has not since been withdrawn. Verification is offline, so it consults no revocation list.

This page and the key above come from the same website. If this website were compromised, both could be replaced together. Compare the fingerprint with a copy you received another way (a document from us, printed material, a person you know) before you trust a result.

Packs signed before 4 September 2026 were signed with the previous key and keep verifying against it. If a pack names a different key, ask whoever sent it for that key and its fingerprint.

The schemas and vocabulary that packs reference are published at schema.certanix.eu. Verification never fetches them: the verifier carries its own copy, and a pack verifies with no network.

Verify in this browser

This runs certanix-verify, the same Python code as the command-line tool, inside your browser through Pyodide. Nothing about verification is reimplemented in JavaScript.

One dependency differs. The browser uses cryptography 47.0.0, the build Pyodide provides; the command-line tool pins cryptography 48.0.1. On every public test case of certanix-verify 0.15.0 (68 cases, each in JSON and in plain-text output, and again through show for the 52 that are packs, byte-exact files or standalone artifacts), the browser and the command line gave identical results: the same exit code and the same output, byte for byte.

Once a pack has verified, the page also shows what it covers: the system tested, the task and its pass criterion, the results, when and where it ran, the linked artefacts and the regulation clauses its evidence relates to. This is certanix-verify show, read only from the signed content and shown as plain text. A pack that does not verify shows its verdict and nothing from its contents.

Your file never leaves this browser. It is read from your disk into this page's memory and verified there. Once the verifier has loaded, the page makes no network connection of any kind: its content security policy forbids it, and the page checks that the browser enforces this before it accepts a file.

Verify on the command line

    
Install

    
Python 3.10 or later. The tool needs the standard library and two pinned packages, and nothing else.


python3 -m pip install certanix-verify

    
For a machine with no network: download on a connected machine, carry the files across, install from them.


# connected machine
python3 -m pip download certanix-verify -d certanix-verify-wheels
# offline machine
python3 -m pip install --no-index --find-links certanix-verify-wheels certanix-verify


    
Check the key


curl -O https://certanix.eu/verify/keys/certanix-hsm.pub
openssl pkey -pubin -in certanix-hsm.pub -outform DER | openssl dgst -sha256

    
The output must read 5849077784fa60616ea83e8bff35c8b294e17631a42435cd20192dd09d9f9ae5. Without openssl (Windows, for instance), the same value from Python:


python3 -c "import hashlib,sys;from cryptography.hazmat.primitives import serialization as s;k=s.load_pem_public_key(open(sys.argv[1],'rb').read());print(hashlib.sha256(k.public_bytes(s.Encoding.DER,s.PublicFormat.SubjectPublicKeyInfo)).hexdigest())" certanix-hsm.pub


    
Verify


certanix-verify verify evidence-pack.json --key certanix-hsm.pub
echo $?   # 0 = verified; any other value is the reason it did not

    
Add --json for one machine-readable object. certanix-verify --help lists the other modes.

    
To see what a pack covers once it has verified (the same summary this page shows):


certanix-verify show evidence-pack.json --key certanix-hsm.pub

    
The exit code is the verification result, as for verify. The clauses listed are what the evidence relates to: a pack is evidence, not a conformity assessment.

Exit codes

    
The exit code is the reason, so a script can act on why a pack failed without reading text.

    

      
CodeClassMeaning

      
        
0OKSignature valid over the canonical bytes; schema valid; no gate violation.

        
1USAGECould not start: unreadable file, missing key, bad invocation. Says nothing about the pack.

        
2MALFORMED_INPUTNot readable as a JSON object (for example, truncated).

        
3SCHEMA_INVALIDReadable, but does not match the schema. The signature was not reached.

        
4UNSUPPORTED_SCHEMA_VERSIONA schema version or artifact type this verifier does not know. Refused rather than guessed.

        
5SIGNATURE_MISSINGThe pack carries no signature.

        
6SIGNATURE_MALFORMEDA signature is present but cannot be decoded.

        
7SIGNATURE_MISMATCHThese are not the bytes that were signed, or not under this key.

        
8KEY_MISMATCHThe signature names a different signer from the key supplied.

        
9GATE_VIOLATIONSigned and well formed, but claims a capability its recorded gate denies.

      
    

    
Codes 10 to 13 belong to certanix-verify vault, which checks a trusted timestamp record.
